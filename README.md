# Яндекс Алиса + Gemini + Serper: облачный вебхук

Готовый вебхук для навыка Яндекс Алисы. Gemini отвечает на вопросы, Serper при необходимости ищет свежие данные в интернете. Вебхук работает на **Netlify Functions** или **Vercel**, а не на вашем компьютере. Если Vercel недоступен, используйте Netlify по инструкции ниже.

Это улучшенная версия шаблона [alice-gemini-serper-template](https://github.com/ruslanpodzorovraw-collab/alice-gemini-serper-template).

## Что улучшено

- **Исправлен выход за лимит `session_state`.** Яндекс разрешает не больше 1 КБ состояния сессии, а исходная версия могла сохранять туда около 19 КБ. Теперь история автоматически сокращается до безопасного размера с сохранением последней пары «вопрос — ответ».
- **Ответы очищаются для озвучки.** Убираются Markdown, ссылки, эмодзи и служебные пометки. Служебные части ответа Gemini с рассуждениями (`thought`) больше не попадают в озвучку.
- **Поиск стал точнее.** Вместо срабатывания на слова «сейчас» и «сегодня» используются темы (погода, новости, курсы, матчи, билеты и т. п.) и явные команды («найди», «поищи»). Из запроса убираются «Алиса», «пожалуйста» и лишние слова.
- **Поисковая выдача стала полезнее.** Учитываются краткий ответ, справка и новости Serper, повторы удаляются, результаты кэшируются на 5 минут.
- **Защита от prompt injection.** Результаты поиска передаются как недоверенные данные, а модели запрещено выполнять инструкции из выдачи.
- **Нормальный жизненный цикл диалога.** Есть приветствие, помощь, завершение по команде «пока»/«хватит» и кнопки-подсказки для устройств с экраном.
- **Ограничение ввода.** Слишком длинная реплика обрезается до 1000 символов, чтобы не тратить лимиты API.
- **Понятные ошибки.** Отдельные сообщения для неверного ключа, недоступной модели, превышения квоты и таймаута.
- **Опциональная защита вебхука.** Переменная `YANDEX_SKILL_ID` разрешает запросы только от вашего навыка.
- **Тесты без внешних зависимостей.** `npm test` проверяет основные сценарии; для работы навыка на вашем ПК ничего запускать не нужно.
- **Актуальные дата и время.** Модель знает текущую дату и время в заданном часовом поясе.

## Размещение на Netlify без запуска на своём ПК

1. На GitHub создайте **новый пустой репозиторий** (**+ → New repository**). Не делайте Fork исходного шаблона: в нём нет улучшений из этой папки.
2. В новом репозитории выберите **Add file → Upload files**. Перетащите **содержимое этой папки** (включая `api/index.js`, `netlify/functions/alice.mjs`, `netlify.toml`, `public/index.html` и `.node-version`), а не ZIP-файл. Проверьте, что файлы лежат в корне репозитория без дополнительной вложенной папки. Не загружайте `.env` и API-ключи. Нажмите **Commit changes**.
3. Откройте https://app.netlify.com/ и войдите или создайте учётную запись. Выберите **Add new project → Import an existing project → GitHub**, предоставьте доступ к своему репозиторию и выберите его.
4. При импорте оставьте **Base directory** пустой (корень репозитория). Конфигурация `netlify.toml` уже указывает каталог публикации `public` и расположение функций; команда сборки не нужна. Нажмите **Deploy** и дождитесь завершения.
5. В проекте Netlify откройте **Project configuration → Environment variables** (названия пунктов могут отличаться).
6. Создайте переменные окружения для функций (scope **Functions**, если он предлагается; deploy context **Production**):
   - **GEMINI_API_KEY** — ключ из Google AI Studio: https://aistudio.google.com/app/apikey
   - **SERPER_API_KEY** — ключ из Serper: https://serper.dev
7. После изменения переменных запустите **новое развёртывание** в Netlify (Deploys → Trigger deploy) и дождитесь завершения. Переменные должны быть доступны функции в Production.
8. Скопируйте адрес сайта Netlify и добавьте `/api`. Например: `https://YOUR-PROJECT.netlify.app/api`. Откройте адрес в браузере: ответ должен содержать `"ok": true` и `"geminiConfigured": true`.
9. Откройте свой навык в [Яндекс Диалогах](https://dialogs.yandex.ru/developer). В настройках Backend вставьте этот полный адрес в **Webhook URL** и сохраните изменения.
10. Проверьте навык во встроенном разделе **Тестирование** Яндекс Диалогов. Вебхук должен быть доступен Яндексу по публичному HTTPS-адресу Netlify.

Используйте только свой домен Netlify — не копируйте адрес автора шаблона. Для истории в пределах одной сессии используется `session_state` из протокола Яндекс Диалогов; отдельное хранилище данных включать не требуется. Доступность Netlify и сторонних API зависит от вашей сети и региона; это нельзя подтвердить до реального развёртывания.

Если у вас ZIP, сначала распакуйте его и выполните шаги выше с содержимым распакованной папки. GitHub не распаковывает загруженный ZIP автоматически.

### Другие площадки

Проект по-прежнему поддерживает Vercel через `api/index.js` и `vercel.json`: импортируйте тот же GitHub-репозиторий в Vercel, добавьте ключи в **Settings → Environment Variables → Production**, повторно разверните проект и используйте `https://ВАШ-ДОМЕН.vercel.app/api`. Если и Netlify недоступен, возможны облачные функции Яндекса, но для них потребуется отдельный адаптер, настройка облака и проверка доступа из него к Gemini и Serper; текущая папка не развёртывается в Yandex Cloud автоматически.

## Переменные окружения

| Переменная | Обязательна | Назначение |
|---|---|---|
| `GEMINI_API_KEY` | Да | Ключ Google AI Studio для ответов Gemini. |
| `SERPER_API_KEY` | Нет | Включает поиск в интернете. Без него обычные ответы Gemini работают. |
| `GEMINI_MODEL` | Нет | Модель Gemini. По умолчанию `gemini-3.5-flash-lite`. Можно писать с префиксом `models/` или без него. |
| `TIME_ZONE` | Нет | Часовой пояс для даты и времени в ответах. По умолчанию `Europe/Moscow`. |
| `YANDEX_SKILL_ID` | Нет | ID навыка из Яндекс Диалогов. Если задан, вебхук принимает запросы только от этого навыка. |

Ключи вводятся только в **Netlify → Environment variables** (либо в настройках Vercel, если выбран он). Не размещайте их в исходном коде, GitHub, README, Яндекс Диалогах или сообщениях. Если ключ попал в открытый доступ, отзовите его и создайте новый.

### Как узнать `YANDEX_SKILL_ID`

ID навыка виден в запросах Яндекс Диалогов в поле `session.skill_id`, а также в настройках навыка. Эта переменная не обязательна: без неё вебхук работает как обычный публичный обработчик. Если вы её задали, запросы без совпадающего `skill_id` получают ответ `403 Forbidden`.

## Как проверить навык без команд и программирования

**Самый простой способ — проверить голосом на колонке или через приложение с Алисой.**

1. Убедитесь, что в Яндекс Диалогах у навыка указан ваш адрес Netlify в поле **Webhook URL**, который заканчивается на `/api`.
2. В настройках навыка выберите тип доступа **Приватный** и сделайте навык доступным для тестирования. Для голосового запуска войдите на колонке или в приложении с Алисой в тот же аккаунт Яндекса, которым пользуетесь в консоли разработчика.
3. Скажите: **«Алиса, запусти навык [название или активационное имя вашего навыка]»**.
4. Когда Алиса запустит навык, задайте обычный вопрос и проверьте, что она отвечает.

Если Алиса не находит навык или вы ещё не сделали его доступным для голосового запуска, откройте Яндекс Диалоги → свой навык → **Тестирование**. Этот встроенный тестер подходит для первой проверки до публикации и показывает ответ навыка.

Если всё работает в тестере, но не работает через колонку, проверьте, что навык доступен для голосового запуска, на колонке выбран тот же аккаунт Яндекса и произносится правильное активационное имя. Инструкция Яндекса: https://yandex.ru/dev/dialogs/alice/doc/ru/test

## Проверка вебхука

`GET /api` возвращает состояние конфигурации без секретов:

```json
{
  "ok": true,
  "service": "alice-gemini-serper",
  "version": "1.1.0",
  "model": "gemini-3.5-flash-lite",
  "geminiConfigured": true,
  "searchConfigured": true,
  "skillIdConfigured": false,
  "timeZone": "Europe/Moscow"
}
```

Если `geminiConfigured` равно `false`, ключ не сохранился или выбран не тот deploy context/scope. После изменения переменных запустите новое развёртывание.

## Тесты для разработчика (необязательно)

Если хотите менять код, можно запустить `npm test` и `npm run check` с Node.js 22 или новее. Для размещения через GitHub и Netlify и тестирования в Яндекс Диалогах Node.js на вашем компьютере не требуется.

## Как это работает

1. Яндекс отправляет POST-запрос с репликой пользователя и историей сессии.
2. Обработчик проверяет команды завершения и помощи, затем определяет, нужен ли поиск.
3. При поисковом запросе Serper получает очищенный запрос и возвращает краткий ответ, справку и ссылки на результаты.
4. Gemini получает системную инструкцию, историю, вопрос и (если есть) результаты поиска.
5. Ответ очищается от Markdown, ссылок и эмодзи, обрезается до 1024 символов и возвращается Алисе вместе с обновлённой историей.

## Ограничения

- **Время ответа.** Яндекс Диалоги ждут ответ около 4,5 секунды. В шаблоне общий бюджет — 3,6 секунды: до 0,7 секунды на поиск и до 2,6 секунды на Gemini. При медленной сети сервер вернёт короткое сообщение с просьбой повторить вопрос.
- **Размер состояния.** `session_state` ограничен 1 КБ, поэтому история намеренно короткая. Это нормально: Алиса помнит последнюю пару реплик, а не весь длинный разговор.
- **Длина ответа.** Не больше 1024 символов, как требует протокол Яндекс Диалогов.
- **Поиск.** Если `SERPER_API_KEY` не задан, поиск полностью отключён, но Gemini продолжает отвечать на обычные вопросы.
- **Модель.** Если `gemini-3.5-flash-lite` недоступна для вашего ключа, укажите в `GEMINI_MODEL` точное имя другой модели Gemini.

## Если навык не отвечает

1. Проверьте, что имена переменных написаны без опечаток и выбран контекст **Production** и scope **Functions** (если доступен).
2. После изменения ключей запустите новое развёртывание и дождитесь его завершения.
3. Проверьте правильность **Webhook URL**: домен должен быть вашим, путь должен заканчиваться на `/api`.
4. Откройте `GET /api` в браузере и посмотрите, какие ключи видит сервер.
5. Откройте **Functions → Logs** в Netlify и проверьте ошибки. Перед отправкой логов удалите из них секретные данные.

Типичные сообщения:

- **«Сервер пока не настроен»** — не задан `GEMINI_API_KEY`.
- **«Не удалось подключиться к Gemini»** — ключ отклонён, создайте новый.
- **«Модель Gemini недоступна»** — проверьте `GEMINI_MODEL`.
- **«Превышен лимит запросов»** — квота Gemini исчерпана, попробуйте позже.
- **`403 Forbidden`** — задан `YANDEX_SKILL_ID`, но запрос пришёл от другого навыка или без `skill_id`.

## Безопасность и приватность

- Текст реплик не пишется в логи. Логируются только длительность, факт поиска, имя модели и код ошибки.
- При поисковом запросе текст уходит в Serper, при обычном ответе — в Gemini. Это неизбежная часть работы навыка.
- Результаты поиска считаются недоверенными данными: модели запрещено выполнять инструкции из выдачи.
- `YANDEX_SKILL_ID` не является секретом, но помогает отсечь случайные запросы к вашему вебхуку.
- Не храните ключи в репозитории. `.env` уже добавлен в `.gitignore`.
